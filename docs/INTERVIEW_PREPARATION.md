# Engineering interview preparation

[README](../README.md) · [Architecture](ARCHITECTURE.md) · [Testing](TESTING.md)

1. **What is the architecture, and why?** A layered monolith: controllers, contracts, domain, scoped services and EF mappings inside one API project. A single database transaction can protect ERP documents, balances and audit records without distributed coordination. It is not a claim of independently deployable modules.
2. **How is dependency injection used?** ASP.NET Core registers the DbContext and business services with request scopes. Controllers delegate business operations; services share the scoped transaction/context. Singleton services must not capture a scoped DbContext.
3. **How do you improve EF Core performance?** Inspect actual SQL, project DTOs, avoid unnecessary tracking, filter/page on the server, and measure before adding indexes. Production preview now filters stock by recipe material IDs instead of materializing an entire warehouse.
4. **Why PostgreSQL transactions?** Stock, movements, document status and audit records must commit together. Database constraints and deferred checks provide relational protection beyond application validation; rollback removes every staged change.
5. **How are concurrent deductions protected?** Writers follow a consistent document → warehouse → product → balance lock order. Under competing requests, stock checks run against locked balances; insufficient stock rejects the operation without partial deductions.
6. **What does idempotency mean here?** Repeating a completed operation must not duplicate its stock effects. Goods receipt replay is tied to a user/key and payload fingerprint; transfer and production commands recognize safe retries and retain original movements.
7. **How does RBAC work?** Admin, Manager and Viewer map to server policies. Managers can perform business writes; administration and selected governance actions require Admin. The frontend reflects the same matrix, but server authorization is the security boundary.
8. **How are JWTs revoked?** Every protected request validates signature, issuer, audience and lifetime, then checks the current user's active state, role and SecurityVersion in PostgreSQL. Deactivation or a security-version/role change invalidates previously issued tokens.
9. **What belongs in a unit/component test?** Deterministic behavior with fast feedback: status labeling, validation, locale state, permission decisions and accessible feedback. Tests should observe behavior rather than duplicate implementation details or claim relational guarantees.
10. **Why real PostgreSQL integration tests?** EF InMemory cannot prove SQL translation, constraints, locking, deferred triggers or transaction rollback. Testcontainers creates isolated real PostgreSQL databases and applies the actual migrations.
11. **What does Playwright add?** It exercises the real built browser application: authentication, forms, navigation, dialogs, language switching and business workflows. Separate smoke and full suites keep feedback useful; axe checks supplement manual accessibility review.
12. **What does GitHub Actions verify?** Backend restore/build/Testcontainers tests; frontend install/lint/type/component/build/audit; separate disposable Compose smoke/axe. No AI provider key or deployment credential is needed. Local execution does not prove an unrun remote workflow.
13. **What deployment decisions matter in Docker?** Multi-stage builds, dependency caching, non-root runtime, persistent database volume, unexposed PostgreSQL and meaningful readiness. Liveness must survive a database outage; migrations and backup recovery need an operational strategy.
14. **How are React components organized?** Route modules load on demand, a common shell handles navigation/context, TanStack Query manages server state, and shared primitives cover loading/status/progress/feedback. Existing forms retain React Hook Form/Zod without an oversized table abstraction.
15. **Why these UI/UX decisions?** Forest green and restrained semantic colors create hierarchy while readable labels convey status independently of color. Grouped navigation, responsive panels/tables, visible focus, native dialogs and localized feedback improve everyday ERP tasks. Automated checks do not certify complete WCAG conformance.
